VXLAN-EVPN Fabric Migration

Migrating a production enterprise fabric from spanning-tree to a VXLAN-EVPN overlay — without a maintenance-window outage, and without breaking the MPLS core it depends on.

Summary: Lead Architect. Designed and executed the migration of a production datacenter network from a spanning-tree topology to a BGP EVPN-signalled VXLAN overlay. Phased parallel-run cutover; MPLS core integration sustained throughout; zero service interruption across a 20+ switch fabric carrying 300+ VLANs.

VXLAN-EVPN BGP MPLS Protocol Migration

Problem

The existing fabric ran classic spanning-tree: blocked links, large L2 failure domains, and change windows where a single misstep could take down a broadcast domain. The topology had become the ceiling on growth — new workloads needed L2 adjacency across the fabric, and every extension made the failure domain larger. The business need was capacity and change-safety; the technical answer was an overlay.

Environment

  • Production enterprise datacenter fabric, multi-vendor environment
  • MPLS core connectivity and DWDM inter-datacenter transport in active use
  • 20+ leaf/spine switches; 300+ VLANs mapped to VXLAN VNIs

Constraints

  • No service interruption acceptable — production workloads served throughout
  • MPLS integration had to remain functional at every phase of the migration
  • Legacy segments could not all move at once; the design had to tolerate a long coexistence period between STP and EVPN domains
  • Changes restricted to agreed maintenance windows with verified rollback at each step

Role and ownership

Lead Architect: owned the target design, the migration sequencing, and the cutover execution strategy. Coordinated implementation across network engineering and datacenter operations; authored the runbooks each phase was executed from.

Architecture decisions

Parallel-run over flag-day cutover. Options considered: staged flag-day migration per segment vs. running the EVPN overlay in parallel with the legacy STP domain and moving workloads gradually. Chosen: parallel-run. A flag-day approach concentrated all risk into single windows with limited rollback; parallel-run made every move individually reversible. Cost: longer coexistence period and temporary complexity at the L2/L3 boundary — accepted deliberately.

BGP EVPN as the control plane. Static VXLAN (flood-and-learn) was rejected: it scales MAC learning poorly and gives no policy control. EVPN provides MAC/IP reachability via BGP, ARP suppression, and a clean integration story with the existing BGP/MPLS edge.

Sustain MPLS integration during migration, not after. Rebuilding the MPLS edge post-migration was rejected — it would have decoupled two risky changes into two risky projects. The boundary between overlay and MPLS core was designed and validated first, then held stable while segments migrated behind it.

Implementation

Phased execution: overlay fabric built and validated alongside production; boundary to the MPLS core established and soak-tested; workload segments migrated in planned waves inside agreed windows, each with pre-verified rollback; legacy STP domain progressively drained and decommissioned. Validation at each wave covered reachability, failover behaviour, and telemetry baselines before the next wave was approved.

Results

  • Zero service interruption across the full migration
  • L2 failure domains eliminated in favour of a routed underlay with ARP-suppressed overlay
  • Change risk profile transformed: segment moves became routine, reversible operations
  • Link and device failover cut from tens of seconds of STP reconvergence (~30–50s) to sub-second ECMP reroute
  • New segment provisioning reduced from a multi-day change process to minutes, via Ansible-driven repeatable workflows

Lessons learned

The coexistence period is the real project. The target architecture was the easy part; most of the design effort went into making the *intermediate* states safe — every wave had to leave the network in a fully supportable condition, because production doesn't pause while you migrate.

Technical notes

  • Overlay: VXLAN data plane, BGP EVPN control plane, ARP suppression enabled
  • Underlay: routed fabric; integration with existing BGP/OSPF and MPLS core
  • Validation: TIG-stack telemetry baselines per wave; state compared pre/post cutover
  • Runbooks: per-wave execution and rollback procedures, authored as part of the design
