SASE / Zero Trust Remote Access Migration

Replacing a legacy full-tunnel VPN platform with SASE-based Zero Trust access for roughly 4,000 users — without weakening the segmentation that protected administrative networks.

Context: Finnish enterprise remote-access estate; roughly 4,000 users and 50+ internal applications moved toward identity-scoped access.

Summary: Lead Architect. Designed, architected, and engineered the modernization of enterprise remote access from a legacy VPN platform to a SASE-based Zero Trust solution (Zscaler) supporting approximately 4,000 users. Full-tunnel VPN eliminated; strict admin network segmentation maintained throughout.

Zero Trust SASE Zscaler Cloud Security

Problem

Remote access ran on a legacy full-tunnel VPN: every remote user landed on the network with broad reachability, all traffic hairpinned through central concentrators, and access policy was network-location-based rather than identity-based. The model concentrated risk (a compromised endpoint inherited network-level access) and concentrated load (all remote traffic through one chokepoint). End-of-life pressure on the platform forced the decision point.

Environment

  • Enterprise environment, approximately 4,000 remote-access users
  • Legacy VPN platform with full-tunnel architecture and centralized concentrators
  • Strictly segmented administrative networks that had to remain isolated from the user access plane
  • 50+ internal applications and services inventoried and mapped to identity-based access policy

Constraints

  • No loss of access for the user population during migration — remote work is the business
  • Admin network segmentation could not be relaxed at any phase, including transition states
  • Coexistence: legacy VPN and SASE platform had to operate side by side during phased rollout
  • Access policy had to become auditable and identity-based, not implied by network location

Role and ownership

Lead Architect: owned the target architecture, platform selection input, policy model design, and migration sequencing. Defined the segmentation strategy that separated the user access plane from administrative planes, and the rollout plan that moved user groups in controlled waves.

Architecture decisions

Application-scoped access over network-scoped access. Recreating the VPN's network-level reachability inside the SASE platform was rejected — it would have modernized the transport while preserving the trust flaw. Access is granted per application and identity, so a compromised endpoint no longer inherits a network.

Admin access stays on its own plane. Folding administrative access into the same user-facing Zero Trust deployment was rejected. Administrative networks kept strict, separate segmentation; the user migration was not allowed to become a backdoor into infrastructure management.

Phased coexistence over big-bang cutover. User groups migrated in waves with the legacy VPN as a live fallback, so every wave was reversible and helpdesk load stayed bounded. Cost: running two access platforms in parallel for the transition period — accepted as the price of a safe migration at this user count.

Implementation

Policy model designed first: applications inventoried, access mapped to identities and groups, and the default changed from "reachable unless blocked" to "invisible unless granted." Pilot group validated the client experience and policy behaviour; rollout then proceeded in planned waves across the ~4,000-user population, with the legacy platform drained progressively and decommissioned at the end.

Results

  • Full-tunnel VPN eliminated; legacy platform decommissioned
  • ~4,000 users migrated to identity-based, application-scoped Zero Trust access
  • Admin network segmentation preserved intact through every migration phase
  • Lateral-movement exposure from compromised remote endpoints structurally reduced
  • €50–100k/yr in legacy platform costs eliminated: licensing, support, and an avoided concentrator hardware refresh
  • Remote-access support tickets roughly halved once the rollout stabilised

Lessons learned

The application inventory is the hard part, not the platform. Zero Trust forces you to make explicit every access relationship the VPN allowed implicitly — surfacing that undocumented reality was the majority of the work, and it left the organization with an asset it never had before: an accurate map of who needs what.

Technical notes

  • Platform: SASE architecture (Zscaler), identity-driven access policy
  • Policy model: per-application access scoped to identity and group; no network-level grants
  • Segmentation: administrative planes isolated from the user access plane throughout
  • Rollout: pilot → wave-based migration with live legacy fallback → decommission
